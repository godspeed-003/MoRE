\section{Experimental Setup}
\label{sec:setup}

\subsection{Data and split}
\label{sec:data}

All arms train on WikiText-103 \citep{merity2017wikitext} with a byte-pair
vocabulary of 8{,}192 tokens and packed sequences of length 256
(\texttt{lang-\allowbreak wikitext-\allowbreak 103-\allowbreak bpe8192-\allowbreak len256-\allowbreak 800d6154}). We use the corpus's own
author-provided validation split rather than carving one out of the training
material, which is what makes the leakage audit in \S\ref{sec:integrity}
meaningful: no validation or test token was ever available to the trainer.

The baseline floor is a backoff bigram estimated on the same corpus:
\textbf{4.9849 nats/token} (7.19 bits, perplexity 146.2). A model that does not
beat it has learned nothing a two-column count table could not. All three arms
beat it, by margins of $+1.037$, $+1.470$ and $+1.348$ nats for MoE, MoR and MoRE
respectively.

\subsection{Training protocol}\label{sec:protocol} Five seeds per arm; 3 epochs of AdamW (lr $10^{-3}$, weight decay $10^{-4}$, clip 1.0, dropout 0.1), $d_{\text{model}}=256$, one block, 4 heads, $T=7$, batch 48, each run on a single GPU (\S\ref{sec:honesty}). Settings were fixed once, before the comparison, and not swept per architecture. \textbf{Three epochs is a fixed compute budget, not convergence}---every arm gets the identical budget, so the comparison is valid though no arm is converged (Appendix~\ref{app:protocol}).
\subsection{Metrics}\label{sec:metrics} The primary metric is \textbf{validation task loss}, final-epoch per-token cross-entropy in nats; \texttt{best} equals \texttt{last} on all 15 cells, so \emph{no model selection occurred}. Routing is scored with permutation-invariant measures (AMI, Hungarian, purity) against a per-run shuffled-label control and reported as a z-score. Depth is reported with its exit rates alongside: a depth--difficulty correlation on an arm whose tokens almost all reach the ceiling is taken against a near-constant and \textbf{says nothing about allocation}. Compute is inference FLOPs per token, counted on a real forward pass at each arm's measured mean depth (Appendix~\ref{app:flops}). Appendix~\ref{app:metrics} defines the rest.

\subsection{Statistics}
\label{sec:stats}

Comparisons use an exact two-sided randomization test on the difference of means,
which enumerates every way of splitting the pooled values into groups of the
original sizes---$\binom{10}{5} = 252$ at five-versus-five---and counts the
fraction whose $|$mean difference$|$ is at least the observed one. It is
exhaustive, hence deterministic: no sampling error, no seed, no normality
assumption, and no threshold to choose. The superseded $k\times$std heuristic is
not used anywhere.

The \textbf{resolution floor} of this design --- the smallest $p$ it can return at
all --- is $2/\binom{n_a+n_b}{n_a}$ for equal arms, which is $2/252 = 0.00794$ at
five-versus-five. The factor of two is there because the two-sided statistic is
invariant under swapping the groups, so extreme regroupings arrive in mirror pairs
and the count at the extreme can never be one.
The derivation is in Appendix~\ref{app:floor}.
\textbf{Every headline comparison in this paper sits exactly on that floor}, which
we phrase as ``as extreme as a five-seed design admits''---a weaker statement than
significance, and not to be dressed up as a stronger one. Only more seeds can
strengthen these claims; no larger effect can.

The correction is Holm--Bonferroni over two pre-registered families (predictive quality, $m=4$; adaptive depth, $m=2$), declared before the final arm was trained. Every headline comparison clears its threshold, and would clear plain Bonferroni even with all six declared comparisons pooled into one family ($0.05/6=0.00833$, a margin of 0.0004 over the floor); Appendix~\ref{app:stats} gives the memberships.

\subsection{Integrity checks}\label{sec:integrity} Three invariants hold across the matrix, each enforced by an automated check: inputs are \textbf{bit-identical across arms} for the same record; the target is absent from the input and no oracle routing label is encoded in a feature slot; and the arms are parameter-matched to $0.069\%$ with seed-blind configurations identical within each arm, so comparability rests on a frozen specification rather than on one code revision. Appendix~\ref{app:integrity} lists them with the structurally-zero loss terms.
