\section{Experimental Setup}
\label{sec:setup}

\subsection{Data and split}
\label{sec:data}

We use two tasks. The language task, described here, measures the three arms on
a realistic vocabulary. The arithmetic task, described in
\S\ref{sec:arith-task}, is built so that the architecture's own assumption is
testable: that operation-typed computations deserve separate parameters and
different amounts of recursion.

All arms train on WikiText-103 \citep{merity2017wikitext} with a byte-pair
vocabulary of 8{,}192 tokens and packed sequences of length 256
% The literal identifier is 41 characters of \texttt, and TeX sets
% \hyphenchar to -1 for typewriter, so it cannot break anywhere and ran 98pt
% past the margin. Short phrase here, literal string in the appendix.
(identifier in Appendix~\ref{app:protocol}). We use the corpus's own
author-provided validation split rather than carving one out of the training
material, which is what makes the leakage audit in \S\ref{sec:integrity}
meaningful: no validation or test token was ever available to the trainer.

The baseline floor is a backoff bigram estimated on the same corpus:
\textbf{4.9849 nats/token} (7.19 bits, perplexity 146.2). A model that does not
beat it has learned nothing a two-column count table could not. All three arms
beat it, by margins of $+1.037$, $+1.470$ and $+1.348$ nats for MoE, MoR and MoRE
respectively.

\subsection{Training protocol}\label{sec:protocol} Five seeds per arm; 3 epochs of AdamW (lr $10^{-3}$, weight decay $10^{-4}$, clip 1.0, dropout 0.1), $d_{\text{model}}=256$, one block, 4 heads, $T=7$, batch 48, each run on a single GPU (the disclosures in the Limitations section). Settings were fixed once, before the comparison, and not swept per architecture. \textbf{Three epochs is a fixed compute budget, not convergence}---every arm gets the identical budget, so the comparison is valid though no arm is converged (Appendix~\ref{app:protocol}).
\subsection{Metrics}\label{sec:metrics} The primary metric is \textbf{validation task loss}, final-epoch per-token cross-entropy in nats; \texttt{best} equals \texttt{last} on all 15 cells, so \emph{no model selection occurred}. Routing is scored with permutation-invariant measures (AMI, Hungarian, purity) against a per-run shuffled-label control and reported as a z-score. Depth is reported with its exit rates alongside: a depth--difficulty correlation on an arm whose tokens almost all reach the ceiling is taken against a near-constant and \textbf{says nothing about allocation}. Compute is inference FLOPs per token, counted on a real forward pass at each arm's measured mean depth (Appendix~\ref{app:flops}). Appendix~\ref{app:metrics} defines the rest.


\subsection{The arithmetic task}
\label{sec:arith-task}

Natural language supplies no operation label, so the language comparison can say
what the three arms do but not whether routing and depth are used for their
intended purpose. The arithmetic task is an instrument built to make that
testable, not a benchmark: it removes every route by which the structure could be
faked.

An example is 24 tokens: an operation token, five binary slots carrying the
operation's iteration count $k$, two 16-bit operands as four hex digits each, a
separator, an eight-digit (32-bit) result, and an end token. Sixteen independent
examples are packed into a 384-token row, and rows are group-pure. There is no
chain of thought: the answer digits follow the operands directly, so any
sequential computation must happen in the recursion rather than in the token
stream. The operation's group is never an input---the router sees the operation
token and must infer the family---and a non-iterated operation carries a null
$k$, so the layout is identical for every operation and the slot cannot leak the
group. Only the eight result digits and the end token are scored, 144 of 384
positions per row.

Seven groups, one per expert, come from the task's own manifest: bitwise, shift
and min--max, add--subtract, multiply, divide and modulo, sort and median, and a
final group holding greatest-common-divisor together with the iterated
operation. The iterated operation is a per-nibble recurrence---each digit
updated from itself and its neighbour, plus a constant, modulo 16---applied $k$
times to the eight nibbles of the concatenated operands. One application is a
$256$-case table, so it is learnable at this scale, while the $k$-fold
composition is not shortcut-able and one application costs about one block
application, which is what lets $k$ span the seven-step budget instead of
overshooting it. Training uses $k \in \{1,2,3,4\}$; $k = 5$ is held out inside
the trained range and $k \in \{6,7\}$ beyond it. There is no depth curriculum: no
target depth is supervised, so the per-$k$ average depth is a measurement rather
than a target, and the per-operation depth-allocation error is correctly
\texttt{N/A}.

The training set is 294{,}000 rows, 112.9M tokens, slightly more than
WikiText-103. The protocol mirrors the language one: three arms, five seeds,
3 epochs, batch 48, $d_{\text{model}} = 256$, one block, 4 attention heads,
$T = 7$, with total FFN width matched within the task---seven experts at
multiplier 4 against a single FFN at multiplier 28. MoE and MoRE are
parameter-identical at 4{,}056{,}334; MoR is $0.11\%$ \emph{smaller} at
4{,}051{,}720, so the residual runs against the composition. The loss is masked
cross-entropy over the result digits, not a regression objective. The protocol
was not frozen in advance: these are same-protocol measurements across the three
architectures, and no multiplicity correction is claimed.

\subsection{Statistics}
\label{sec:stats}

Comparisons use an exact two-sided randomization test on the difference of means,
which enumerates every way of splitting the pooled values into groups of the
original sizes---$\binom{10}{5} = 252$ at five-versus-five---and counts the
fraction whose $|$mean difference$|$ is at least the observed one. It is
exhaustive, hence deterministic: no sampling error, no seed, no normality
assumption, and no threshold to choose. The superseded $k\times$std heuristic is
not used anywhere.

The \textbf{resolution floor} of this design --- the smallest $p$ it can return at
all --- is $2/\binom{n_a+n_b}{n_a}$ for equal arms, which is $2/252 = 0.00794$ at
five-versus-five. The factor of two is there because the two-sided statistic is
invariant under swapping the groups, so extreme regroupings arrive in mirror pairs
and the count at the extreme can never be one.
The derivation is in Appendix~\ref{app:floor}.
\textbf{Every headline comparison in this paper sits exactly on that floor}, which
we phrase as ``as extreme as a five-seed design admits''---a weaker statement than
significance, and not to be dressed up as a stronger one. Only more seeds can
strengthen these claims; no larger effect can.

The correction is Holm--Bonferroni over two pre-registered families (predictive quality, $m=4$; adaptive depth, $m=2$), declared before the final arm was trained. Every headline comparison clears its threshold, and would clear plain Bonferroni even with all six declared comparisons pooled into one family ($0.05/6=0.00833$, a margin of 0.0004 over the floor); Appendix~\ref{app:stats} gives the memberships.

\subsection{Integrity checks}\label{sec:integrity} Three invariants hold across the matrix, each enforced by an automated check: inputs are \textbf{bit-identical across arms} for the same record; the target is absent from the input and no oracle routing label is encoded in a feature slot; and the arms are parameter-matched to $0.069\%$ with seed-blind configurations identical within each arm, so comparability rests on a frozen specification rather than on one code revision. Appendix~\ref{app:integrity} lists them with the structurally-zero loss terms.
